# Project Instructions

## Project Documentation

The `docs/` directory contains the official project documentation.

The following documents are the source of truth:

- `docs/SHTAPM_PRD-4.md`

- `docs/SHTAPM_Doc02_TRD.md`

- `docs/SHTAPM_Doc03_AppFlow.md`

- `docs/SHTAPM_Doc04_UIUX_Aurora.md`

- `docs/SHTAPM_Doc05_BackendSchema.md`

- `docs/SHTAPM_Doc06_ImplementationPlan.md`

Read the relevant documentation before implementing any feature.

## Important Rules

- Do not change the approved architecture without asking first.

- Follow the PRD and TRD.

- Follow the database schema defined in the documentation.

- Follow the UI/UX specification.

- Follow the implementation plan phase-by-phase.

- Do not skip planned phases.

- Do not implement future phases unless explicitly asked.

- Do not introduce major technologies or dependencies without asking first.

- Do not modify the project requirements based on assumptions.

- If two documents contradict each other, stop and ask for clarification.

- If something important is missing from the documentation, ask before making a major assumption.

## Development

Before implementing a feature:

1. Read the relevant documentation.

2. Inspect the existing project structure.

3. Explain what you plan to change.

4. Implement only the requested scope.

5. Run appropriate tests or validation.

6. Report what files were created or modified.

7. Mention any deviations from the documentation.

## Code Quality

- Write clean, maintainable code.

- Keep components and modules reasonably separated.

- Follow the conventions of the chosen framework.

- Avoid unnecessary dependencies.

- Do not leave debugging code or temporary files.

- Handle errors properly.

- Never hardcode secrets, API keys, passwords, or tokens.

## Git Safety

Before making large changes, check the current Git status.

Keep changes organized into logical commits.

Do not reset, delete, or overwrite existing work unless explicitly instructed.

## Scope Control

The user controls when implementation moves to the next phase.

Do not continue automatically to later implementation phases after completing the requested phase.
